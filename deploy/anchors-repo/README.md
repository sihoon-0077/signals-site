# SIGNALS 공개 앵커 저장소

SIGNALS({{SITE_URL}})는 AI·퀀트 시그널을 결과가 나오기 전에 봉인해 기록하고, 누구나 그 기록을 대조할 수 있게 하는 서비스입니다.
이 저장소는 SIGNALS의 **일일 앵커**(그날까지의 모든 기록을 머클 루트 하나로 묶어 서명한 문서)를 매일 18시(KST) 무렵 받아 두는 공개 저장소입니다.
플랫폼이 앵커에 담긴 과거 기록을 나중에 지우거나 고치면, 이 저장소에 받아 둔 사본·비트코인 타임스탬프와 맞지 않게 되어 드러납니다.

> 지금 SIGNALS는 출시 전 무료 기록 서비스입니다. 시그널을 판매하거나 결제를 받지 않으며, 투자 조언을 하지 않습니다.
> 이 저장소에는 시그널 내용이 없습니다. 기록의 지문(해시)·건수, 서명·타임스탬프, 공개키만 들어 있고, 이 내용은 투자 권유가 아닙니다.

## 들어 있는 것

| 파일 | 내용 |
|---|---|
| `anchors/YYYY-MM-DD.json` | 그날의 앵커 문서. 모든 에이전트(종료 포함)의 기록 수·마지막 지문(리프), 머클 루트, 직전 루트(`prev_root`), 체크포인트 키 서명, 루트의 RFC 3161 타임스탬프 토큰 |
| `anchors/YYYY-MM-DD.json.ots` | 그 파일의 OpenTimestamps 증명(비트코인 블록에 고정). 처음 몇 시간은 '대기 중'이며 보통 다음 날 실행까지 완성본으로 갱신됩니다 |
| `keys.json` | 서명 공개키 목록. 이 저장소에 이미 올라온 키가 사이트에서 바뀌거나 사라지면 자동 작업이 실패하고 이 파일을 덮어쓰지 않습니다(새 키 추가와 폐기 시각을 새로 적는 것만 반영). 바뀐 적이 있는지는 `git log -p keys.json`으로 볼 수 있습니다 |
| `scripts/`, `.github/workflows/anchor.yml` | 아래 자동 작업의 코드 |
| `requirements.txt` | 검증 도구(Python)의 버전·해시 고정 목록 |

## 자동 작업이 하는 일

매일 KST 18:17 무렵 실행하고, 같은 날 20:47 무렵 한 번 더 실행합니다. GitHub 예약 실행이라 늦어지거나 빠질 수 있습니다.

1. 사이트에 오늘 앵커를 만들게 합니다. 요청에 오늘(KST) 날짜를 함께 보내고, 사이트는 그 날짜가 아직 오늘일 때만 만듭니다. 같은 날짜는 한 번만 만들어지므로 두 번째 실행은 이미 만든 앵커를 받아 대조만 합니다. KST 18시 전에 실행되면(수동 실행 등) 앵커를 요청하지 않고 2~7만 합니다. 이 요청은 별도 job에서 하며, 요청에 쓰는 비밀값은 이 job에만 줍니다(Python 패키지가 도는 job에는 이 비밀값도 쓰기 권한도 없습니다).
2. **공개키 대조**: 이 저장소에 있는 키가 사이트에서 사라지거나 바뀌었으면 실패합니다.
3. **과거 앵커 대조**: 이 저장소에 있는 날짜의 문서가 사이트와 다르거나 사이트에서 사라졌으면 실패합니다(덮어쓰지 않음). 이 저장소에 없는 날짜는 받아 저장합니다. 사이트 목록에 오늘보다 늦은 날짜가 있으면 실패합니다.
4. **별도 구현 검증**(`scripts/verify_anchor.py`, 사이트 코드를 쓰지 않고 Python으로 다시 만든 검증기): 머클 루트 재계산, 리프 정렬, 루트 서명, `prev_root` 사슬, 날짜 사이 대조(에이전트가 사라지거나 기록 수가 줄었는지)를 확인합니다.
5. 새 앵커는 비트코인(OpenTimestamps) 고정을 요청하고, 대기 중인 증명은 갱신합니다.
6. **커밋**: 저장소 쓰기 권한은 이 단계(별도 job)에만 있습니다. 앞 단계가 넘긴 파일은 정해진 이름(앵커 문서·증명·`keys.json`)만 받고(다른 파일이 있으면 실패), 앵커 문서와 `keys.json`은 사이트에서 다시 받아 같은지 확인한 뒤 커밋합니다. 이미 있는 증명은 대기 중에서 완성본으로 바뀔 때만 갱신합니다.
7. **커밋 뒤 증명 점검**: 문서 날짜로부터 이틀이 지난 앵커의 `.json.ots`가 없거나 아직 완성본이 아니면 실행을 실패로 표시합니다(커밋한 앵커는 그대로 둡니다).

앵커는 그날(KST 24시 전)에만 만들 수 있습니다. 만들지 못한 날은 나중에 채우지 않고 빈 날로 남깁니다. 나중에 채우면 그날 이미 고정된 것처럼 보이기 때문입니다. 그 사이 기록은 다음 앵커에 담기고, 다음 날 실행 로그에 빈 날 경고가 표시됩니다.
예약 실행이 실패하거나 빠진 날 관리자가 수동 실행(Run workflow)으로 복구하려면 KST 23:50 전에 시작해야 합니다(재시도를 포함해 몇 분 걸림). 요청이 자정을 넘기면 앵커를 만들지 않고 실패로 끝나며, 그날은 빈 날로 남습니다.

어느 단계든 실패하면 커밋하지 않습니다. 비트코인 고정 단계만 예외입니다. OpenTimestamps 캘린더 서버 장애로 실패하거나 시간 안에 끝나지 않아도 앵커는 커밋하고, 증명은 다음 실행 때 다시 요청·갱신합니다. 커밋 뒤의 증명 점검(7)은 이틀이 지나도 완성되지 않은 증명이 있으면 실행을 실패로 표시합니다(그 실행의 앵커 커밋은 이미 끝난 것입니다).
실패한 실행은 Actions 탭에서 누구나 볼 수 있지만, GitHub 보관 기간(공개 저장소 최대 90일)이 지나면 지워지고 저장소 관리자도 지울 수 있습니다. 오래 남는 흔적은 이 저장소 자체입니다. 만들지 못한 날은 `anchors/`에 그 날짜 파일이 없고, 사이트에서는 만들어졌지만 늦게 받아 온 앵커는 `.ots`(비트코인) 시각이 문서 날짜보다 늦게 나옵니다.

## 직접 확인하는 법

이 저장소를 받은 폴더에서 Python 3.11 이상(3.12 권장)으로 실행합니다.

```bash
python3 -m venv .venv && . .venv/bin/activate                # Windows: py -m venv .venv 후 .venv\Scripts\activate
python -m pip install --require-hashes -r requirements.txt   # 버전·해시를 고정한 도구
python scripts/verify_anchor.py                              # 모든 앵커: 루트·서명·사슬·날짜 사이 대조
ots info anchors/2026-11-02.json.ots                         # 비트코인 증명 내용
```

- 비트코인 증명은 [opentimestamps.org](https://opentimestamps.org)에 `.json`과 `.json.ots`를 함께 올려도 확인할 수 있습니다(`ots verify`는 비트코인 노드가 필요).
- 커밋 기록(`git log --follow anchors/날짜.json`)으로 문서가 들어온 순서를 참고할 수 있습니다. 커밋 시각은 커밋하는 쪽이 정하는 값이라 시각 증거가 아닙니다. 시각 증거로는 `.json.ots`(비트코인)와 문서 안의 RFC 3161 토큰(`timestamps`)을 쓰세요.
- 개별 시그널은 사이트의 검증 페이지 `{{SITE_URL}}/verify/<지문>`에서 확인합니다(에이전트 기록 페이지의 '직접 검증' 링크, 지문은 64자리). 지문 링크를 권합니다. 그 지문을 가진 기록만 통과하므로, 사이트가 다른 기록을 보내면 드러납니다. 검증 페이지는 공개키와 앵커를 이 저장소에서 따로 받아 대조하지만 그 화면의 코드도 사이트가 보내므로, 화면에 나온 앵커 날짜·루트가 이 저장소의 같은 날짜 파일과 같은지 직접 한 번 더 비교하세요.
- 명령줄 검증기는 공개 전이며, 공개하면 여기에 사용법을 적습니다.

## 이 저장소가 증명하지 않는 것

- 시그널의 실력이나 미래 수익, 실계좌 체결. 이 저장소로 확인할 수 있는 것은 "결과 전에 그 내용으로 기록됐고, 일일 앵커로 외부에 고정된 뒤 지우거나 바꾸면 드러난다"까지이며, 성과를 보장하는 것이 아닙니다. 과거 기록이 미래 수익을 보장하지 않으며, 투자 판단과 그 결과의 책임은 투자자 본인에게 있습니다.
- 앵커가 처음 만들어지기 전 구간(그 이전 기록은 각 시그널의 타임스탬프 토큰으로만 확인)
- 저장소 관리자(SIGNALS 운영자)가 이 저장소를 고치지 않았다는 것. 파일을 고치면 커밋 기록에 남고, 강제 푸시로 기록을 다시 쓰면 미리 받아 둔 사본(clone·fork)과 달라집니다. 중요한 날짜는 사본을 직접 받아 두세요.
